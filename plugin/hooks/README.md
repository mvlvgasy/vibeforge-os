# Vibeforge Hooks

> Claude Code lifecycle hooks. Functional scripts with automatic error
> detection, capitalization reminders, and token-saving guards.

These hooks are loaded automatically when the Vibeforge plugin is installed,
via `hooks.json`. Claude Code resolves `${CLAUDE_PLUGIN_ROOT}` to the plugin's
install directory and points each hook at the matching PowerShell script.

## Hooks present

| Event | File | Role |
|-------|------|------|
| `SessionStart` | `session-start.ps1` | Session bootstrap |
| `Stop` | `stop.ps1` | Detects significant activity without register updates -> writes a reminder in `.claude/last-stop-reminder.md`. Also nudges `/save-cadrage` (R018) when framing memory is stale. |
| `SessionEnd` | `session-end.ps1` | Detects whether the session was closed properly, drops a `pending-capitalization.md` otherwise |
| `PreToolUse` (Read) | `pre-tool-use.ps1` | Blocks full-reads (no offset/limit) of large TOC-indexed registers (> 500 lines) to save bootstrap tokens |
| `PreToolUse` (Edit/Write/MultiEdit) | `config-protection.ps1` | Blocks modification of an existing linter/formatter config (prevents loosening the rules to make a check pass) |
| `PreToolUse` (Edit/Write/MultiEdit) | `fact-force.ps1` | Opt-in: blocks the first edit of each file to force a prior investigation (importers, schemas, instruction). No-op unless `VIBEFORGE_FACT_FORCE=1` |
| `PostToolUse` | `post-tool-use.ps1` | Detects errors (non-zero exit codes) + invented files -> appends to `.claude/pending-blockers.md` / `.claude/pending-eval.md`. Also logs metrics, scope-creep / tool-loop warnings, and a memory-update marker for long sub-agents (R009) |
| `PreCompact` | `pre-compact.ps1` | Before a compaction, reminds you to flush framing memory (`MEMORY-cadrage.md`) so decisions/roadmap are not lost (R018) |

## Files generated by the hooks

All gitignored. To review at session close:

| File | Generated by | Content |
|------|-------------|---------|
| `.claude/logs/*.log` | every hook | Per-event logs |
| `.claude/metrics/events.jsonl` | several hooks | Append-only telemetry (tool calls, errors, claims, blocks) |
| `.claude/last-stop-reminder.md` | stop.ps1 | Capitalization reminder when activity occurred without register updates |
| `.claude/verification-required.md` | stop.ps1 | Completion-claim patterns detected in the agent response |
| `.claude/pending-blockers.md` | post-tool-use.ps1 | Auto-detected blocker candidates (Bash/PowerShell errors) |
| `.claude/pending-eval.md` | post-tool-use.ps1 | Eval pattern candidates (invented files, etc.) |
| `.claude/pending-context-warnings.md` | post-tool-use.ps1 | Scope creep / tool loop warnings (non-blocking) |
| `.claude/cadrage-precompact-reminder.md` | pre-compact.ps1 | Pre-compaction reminder to flush framing memory |
| `pending-capitalization.md` | session-end.ps1 | Marker for a forgotten session close |

## Error categories detected by post-tool-use

The hook categorizes errors automatically via regex on stderr:
- `missing-file` (ENOENT, "No such file", "cannot find")
- `permission` ("permission denied", "access denied")
- `syntax` ("syntax error", "unexpected token")
- `missing-dependency` ("ModuleNotFoundError", "Cannot find module")
- `type-error` ("TypeError", "undefined is not")
- `network` ("ENETUNREACH", "connection refused")
- `timeout` ("ETIMEDOUT")
- `unknown` (default if no regex matches)

## Workflow: auto-detection -> formalized blocker

```
Tool call fails (exit != 0)
        |
post-tool-use.ps1 detects it
        |
Appends a candidate to .claude/pending-blockers.md (category + stderr snippet)
        |
Later, at session close:
        |
Reads pending-blockers.md
        |
For each entry, decide:
- Real friction -> promoted to B<NN> in registers/blockers.md (full frontmatter)
- Transient -> ignored, journaled
- Mergeable -> update an existing blocker
        |
pending-blockers.md emptied/archived
```

## Opt-in: fact-force

`fact-force.ps1` is intrusive (it blocks the first edit of every file). It is a
no-op unless you explicitly enable it for a session:

```powershell
$env:VIBEFORGE_FACT_FORCE = "1"
```

Leave it unset to disable entirely (zero risk).

## Security

Hooks have full system access. Always:
- Review the code before enabling
- Avoid destructive commands without validation
- These hooks only write under `.claude/` of the current working directory (plus
  the plugin's own `agent-contexts/` for the R009 marker), never elsewhere

## Platform

Hooks are written in PowerShell for Windows. UTF-8 encoding is forced
(`-Encoding utf8`) to avoid BOM/UTF-16 issues. To port to other operating
systems, create `.sh` equivalents in a future iteration.
