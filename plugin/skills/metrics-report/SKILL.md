# /metrics-report

Generates an empirical report on usage.

## Workflow

1. **Read the log**: `Read` on `${CLAUDE_PLUGIN_ROOT}/metrics/events.jsonl`. If absent or empty → display "No metrics recorded yet. The log is generated by the hooks starting from the next session." and stop.

2. **Filter by period** (default = last 7 days):
   - 7d: events of the last 7 days
   - 30d: 30 days
   - all: full history

3. **Filter by scope** (default = global):
   - global: all cwds
   - lab=<name>: only events where cwd matches the lab folder

4. **Aggregations**:
   - Top 10 invoked tools (by count)
   - Top 5 delegated agents (`kind:agent_delegated`)
   - Top 5 invoked skills (`kind:skill_invoked`)
   - Total `tool_error` by error category
   - Sessions ended (`kind:session_end`) with and without HANDOVER
   - Completion claims detected (`kind:completion_claim`)

5. **Dormancy**:
   - Compare the invoked skills/agents vs the list of existing skills/agents (`Glob` on `${CLAUDE_PLUGIN_ROOT}/skills/*/SKILL.md` and `${CLAUDE_PLUGIN_ROOT}/agents/*.md`)
   - List skills/agents **never** invoked in the period
   - List those invoked <1 time/week (candidates for archiving or consolidation)

6. **Rules** (if possible):
   - Read `<workspace>/registres/rules.md`
   - Count references to each rule (R001, R002...) in the events (eventually instrumented, for now approximated by a text scan on the cited file paths)

7. **Output**: structured Markdown, write into `<workspace>/metrics/reports/report-<YYYY-MM-DD>.md` (create the folder if needed). Also display on screen.

## Guardrails

- If `events.jsonl` is too big (>10 MB) → use `Bash` with `tail -n 50000` to limit the read.
- Malformed JSON on a line → skip it, do not crash.
- The report is an **observation**, not a decision. The actions (archive a skill, remove an agent) stay human: you list the candidates, the operator decides.
- Anti-pattern: **do not modify events.jsonl**. Read-only.

## Living data

The log grows on each session turn, automatically, without intervention. The more sessions, the more precise the report. Patience: the first week the numbers are sparse.

## Focus mode `memory-consolidation` (R009 Phase B)

If `$ARGUMENTS` contains `--focus=memory-consolidation`, generate a report specific to R009 metrics:

### Computed metrics

1. **`dream_acceptance_rate`** (target >50%):
   - Numerator: sum of `apply_k` of `kind:"dream_run"` events in the period
   - Denominator: sum of `propositions_n` of the same events
   - Meaning: % of the dreamer's proposals approved by the validator

2. **`tc_follow_rate`** (target 30-70%):
   - Numerator: count of `kind:"tc_follows_dream"` events in the period
   - Denominator: count of `kind:"dream_run"` events with `signals_tc>0` in the period
   - Meaning: % of the times a dreamer signal leads to a traffic-controller scan within 7d

3. **`dream_cadence`** (target 2-4 days):
   - Computation: successive timestamps of `kind:"dream_run"` events, average gap in days
   - Meaning: actual frequency vs target cadence (~1x/day for auto, ~2-4d for normal usage)

4. **`tc_invocation_count`** (target >=1/month if projects >=3):
   - Computation: count of `kind:"traffic_controller_run"` events in the period
   - Meaning: to compare to the number of active projects (discipline signal)

### Bash extraction

```bash
EVENTS_FILE="${CLAUDE_PLUGIN_ROOT}/metrics/events.jsonl"
PERIOD_DAYS=30  # adjustable per $ARGUMENTS

# Dream metrics
DREAM_TOTAL_N=$(grep '"kind":"dream_run"' "$EVENTS_FILE" | jq -s '[.[] | .propositions_n // 0] | add // 0')
DREAM_TOTAL_K=$(grep '"kind":"dream_run"' "$EVENTS_FILE" | jq -s '[.[] | .apply_k // 0] | add // 0')
DREAM_ACCEPTANCE_RATE=$(echo "scale=2; $DREAM_TOTAL_K / $DREAM_TOTAL_N * 100" | bc)

# TC follow rate
DREAMS_WITH_SIGNALS=$(grep '"kind":"dream_run"' "$EVENTS_FILE" | jq -s '[.[] | select(.signals_tc // 0 > 0)] | length')
TC_FOLLOWS_COUNT=$(grep -c '"kind":"tc_follows_dream"' "$EVENTS_FILE" || echo 0)
TC_FOLLOW_RATE=$(echo "scale=2; $TC_FOLLOWS_COUNT / $DREAMS_WITH_SIGNALS * 100" | bc)

# Cadence
DREAM_RUNS_COUNT=$(grep -c '"kind":"dream_run"' "$EVENTS_FILE" || echo 0)
FIRST_TS=$(grep '"kind":"dream_run"' "$EVENTS_FILE" | head -1 | jq -r '.ts')
LAST_TS=$(grep '"kind":"dream_run"' "$EVENTS_FILE" | tail -1 | jq -r '.ts')
# Compute average days between dreams via timestamps

# TC invocation count
TC_INVOCATION_COUNT=$(grep -c '"kind":"traffic_controller_run"' "$EVENTS_FILE" || echo 0)
```

echo "{\"ts\":\"$TS\",\"kind\":\"metrics_report_run\",\"focus\":\"memory-consolidation\",\"period_days\":$PERIOD_DAYS}" >> "${CLAUDE_PLUGIN_ROOT}/metrics/events.jsonl"

### When to use this focus

- After >=10 dreams (enough material)
- If the session-end hook posted `.claude/measure-reminder.md` (=10 dreams + 0 metrics-report in 30d)
- Monthly as a periodic audit

### Focus anti-patterns

- Not useful before >=10 dreams (numbers too small, noise > signal)
- Do not confuse with the global `metrics-report` (different: this focus specifically measures R009, not global usage)
